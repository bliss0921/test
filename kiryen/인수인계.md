## 1. 사용자

- **코딩을 전혀 모른다** ("트리거를 만들라는 게 무슨 말인지 몰라"). 설명은 쉬운 한국어로, 전문 용어 없이, "왜 그렇게 되는지" 원리를 짧게.
  사용자가 직접 해야 할 일이 있는지 없는지를 분명히 말한다 (예전에 필요 없는 수동 작업을 안내했다가 "왜 처음에 나한테 트리거 추가하라 했어?" 소리를 들었다).
- 로어북·정규식은 자기가 보고 파악하고 싶어 한다. 화면에서 안 보이는 곳에 뭘 숨기는 걸 싫어한다
  (예: RisuAI는 Lua 칸이 하나만 보이므로 트리거를 따로 새로 만들면 안 보이는 코드가 됨 → 금지). 지금은 완성된 charx 파일을 받는 걸 좋아한다
  ("이번엔 다 바꿔서 charx 파일로 줘도 좋아"). 파일을 주면서 바뀐 점과 사용자가 확인·채울 것을 꼭 알려 준다.
- CBS는 일부 직접 하기도 한다. 작업 도중 말을 끊고 세부를 추가하는 일이 있다 (예: 다프네야 비밀은 일부러 뺐고 다프네야 항목에 넣을 것).
- 참고하는 다른 봇: Callan 봇(언어 토글로 퍼메 언어 전환), 판게아 봇(상태창 형식), 어떤 판타지 봇(인물 이름을 하나하나 적은 엄격한 리퀘 제거 정규식).
- 카드 안 `작성지침` 로어북(키가 공백이라 모델에 안 들어감)은 사용자의 글쓰기 규칙이다. 로어북·설명을 쓸 때 지킨다:
  - 최대한 성중립적 표현, 대명사 대신 이름 (나중에 NPC 성별을 토글로 고르게 하려고).
  - 캐릭터 설명에 기계적인 단어(mechanism, engine, principle 등) 금지. 캐릭터가 "메커니즘 파악 완료" 같은 말을 하게 된다.
- 카드 `description` 맨 위의 줄들(`이름바꾸기 / 상태창 / 디스크립션고쳐 / 봇토글로 / 궁정지도? / 에셋출력 / 퍼메 if도 바꿔 / cbs다바꿔`)은 사용자 할 일 메모다.
  지우지 않는다. 끝난 것: 이름바꾸기, 상태창, 봇토글로, 퍼메 if, cbs. 안 끝난 것: 디스크립션 고치기, 궁정지도, 에셋출력(`에셋출력식` 로어북이 비어 있음).

## 2. 봇의 원칙

- 로판 소설 『황제의 연인』 속에 빙의하는 이야기. 원작에서 카르엔야(황제)는 100일 뒤(IY 429. 9.21) 배우자들의 동시 반역으로 죽는다.
- **플레이어는 다 알아도 되고, NPC는 원작도, 이게 소설이라는 것도 모른다.** 소설이라는 틀은 빙의물의 재미라 모델에게는 알려 주되 {{user}}의 독자 기억으로만 다룬다.
- 미래 이벤트는 모델에게 **지금까지 진행된 일 + 7일 안에 다가올 일**만 보낸다 (Lua가 매 요청마다 계산). 원작소설 로어북에는 소설 틀과 6월 13일까지의 역사만 있다.
  100일 타이머는 플레이어 안내용(상태창 '다가올 일')이지 모델용이 아니다.
- 카르엔야의 능력은 사용자가 자유롭게 정한다. `빙의상태 카르엔야 설정` 끝의 두 줄(`로어북_능력비밀.md`): 쓰면 {{user}}가 묘사한 대로 되고, 남들은 겉 흔적만 보고 평범하게 해석한다.
- 다프네야의 비밀(`로어북_다프네야비밀.md`)은 사용자가 다프네야 항목에 넣는다. 다프네야가 등장할 때만 켜지게.
- **{{user}}는 사람이 연기하는 페르소나다.** 무엇을 알고 어떻게 행동할지는 사용자 입력이 정한다. 그래서 {{user}}의 지식을 막는 지시("{{user}}는 미래를 모른다")나 당연한 호칭 규칙은 넣지 않는다. 호칭 규칙은 남의 몸에 빙의할 때(빙의 토글 0·1)만 필요하다.
  (v4에 넣었던 `유저=빙의없음` 전제를 사용자가 이 이유로 빼자고 했고, 반란 정보는 트리거 World State가 이미 줘서 지웠다.)

## 4. v4 카드 구조

### 토글 (`extensions.risuai.toggles`, 사용자가 준 글 그대로)

`kc_language`(한국어/English), `kc_scenario`(카르엔야에 빙의/다른 인물에 빙의/빙의 없음), `kc_fate`(켜기/끄기),
`kc_g_{karenya,hedwig,piache,ruslan,myusa,daphneya,runian}`(남/여), `kc_p_…`(상세/리스트만).
값은 선택지 번호 문자열 `"0" "1" "2"`, 안 고르면 `"null"` (메뉴에는 빈칸으로 보임). 안 고르면 = 첫 선택지처럼 동작하게 했고,
성별만 원작 성별(카르엔야·다프네야 여, 나머지 남)이다. 그래서 기본값 쪽 조건은 `tisnot`으로 쓴다.
토글 글·키 이름은 사용자가 정한 것이니 함부로 바꾸지 않는다. 언어 토글 설명이 "퍼메 디데이 루아 언어 설정"이라, 본문 출력 언어 지시는 넣지 않았다.

### 첫 메시지

`◆▶◆` 한 줄(정규식 `Start`가 퍼메 패널로 바꿈, `Start 리퀘제거`가 요청에서 지움) 뒤에:
자유 시작 조건(`perma == fm_free` 또는 빙의 토글 1·2)이면 `[IY: ? | ? | ? | ?]`만, 아니면 언어 토글에 따라 영어 자리표시 / 한국어 본문(꿈 장면 → 셀레니아).
`perma`는 채팅 변수(기본 변수 `perma=fm_karenya`), 버튼 `risu-trigger="setPermaKarenya" / "setPermaFree"`가 바꾼다.

### 정규식 (3개)

- `Start` (editdisplay, `◆▶◆`): 퍼메 패널. 카르엔야 빙의 버튼은 빙의 토글 0일 때만, 자유 시작은 항상. 선택된 쪽이 보라색.
  빈 줄이 생기면 마크다운이 HTML 블록을 끊으므로 조건부 버튼은 한 줄 안에 넣었다.
- `Start 리퀘제거` (editprocess, `◆▶◆` → 빈칸).
- `Status 리퀘제거` (editprocess): IN `(?<=\[IY:[^|\]\r\n]*\|[^|\]\r\n]*\|[^|\]\r\n]*?)\s*\|[^\]\r\n]*(?=\])`
  = 세 번째 칸 뒤(능력·속마음) 전부. OUT은 사용자 원래 것 `{{#when::{{greater_equal::{{chat_index}}::{{? {{lastmessageid}}-3}}}}}}` + 빈 줄 + `$&` + 빈 줄 + `{{/when}}`
  → 최근 4개 메시지는 그대로, 나머지는 `[IY: 날짜 | 시간 | 장소]`. 사용자가 판타지 봇처럼 이름을 하나하나 적는 식이 필요하냐고 물었고,
  인물 수가 정해져 있지 않아 필요 없다고 답했다.

### 트리거 (Lua 칸 하나)

퍼메 함수(`setBoth`, `setPermaKarenya`, `setPermaFree`) + `원작타임라인.lua`. 사용자 원래 코드의 성별 패널(`onButtonClick`),
언어·시나리오·난이도 함수, `onStart`는 지웠다. `listenEdit` 두 개만 쓰고 변수는 저장하지 않는다 (low level access 불필요):

- `editRequest`: 최근 AI 답변 STATUS 날짜 → D-남은 날 → `[World State]` 시스템 메모(지난 일 + 7일 안 + 막힌 일 + 규칙)를 마지막 유저 메시지 앞에 끼움.
  모델용 이벤트 이름은 `title_en`. 빙의 토글 2면 "독자의 기억" 문구 대신 중립 문구 ("{{user}}는 미래를 모른다"류 문장도 넣지 않음). 이벤트 본문은 "In the novel" 같은 말 없이 중립으로 썼다.
- `editDisplay`: `[IY: … ]` 줄을 상태창 카드 HTML(한 줄)로 바꿈. 다가올 일은 그 메시지 날짜 + 그 메시지까지의 막힘 표시 기준, 날짜를 모르면 안 보임.
- 막힘 표시: 모델이 STATUS 바로 앞 줄에 `<!-- TIMER: E2 blocked -->`. `needs`/`any`로 뒤 이벤트까지 연쇄로 막힘.

### 배경 HTML (CSS)

`<style>` 하나: Google Fonts `@import`(Gowun Batang, Noto Sans KR) + 퍼메 패널 `.kc-*` + 상태창 `.ks-*`.
테두리는 SVG를 data URI로 CSS에 넣어 에셋이 없다 (`border-image: url("data:…") 40 fill / 30px stretch`, 모바일 24px).
옛 `.imperial-status-card`, `.hgw-*`, `.cgp-*` CSS는 지웠다.

## 5. 상태창 사양

- 모델 출력 (로어북 `Status`): `[IY: 429. 7.15 (D-68) | 15:00 | 기사단 연무장 | 시간 정지 || 헤드비히 | 속마음 || 루스란 | 속마음]`.
  아무도 없으면 `||` 부분 없이 끝. 능력은 정해지기 전엔 미공개/Undisclosed, 없으면 `-`. 9.21 이후는 날짜만.
  인물 수 제한 없음 (5명 테스트함). 속마음은 그 인물이 아는 것만.
- 화면 카드: 1줄 날짜 + D-day(트리거가 날짜로 계산, 0이면 D-Day) / 2줄 시간 · 장소 · 능력 / 가는 선 / 속마음(이름을 문단 맨 앞에 와인색 굵게, 줄바꿈은 왼쪽 끝부터) /
  가는 선 / 다가올 일 3개(오늘 표시 없음). 라벨은 한국어 `능력`·`다가올 일`, 영어 `Ability`·`Upcoming`. 아이보리 바탕 `#faf5ec`, 와인 `#6e1f30`, 금 `#94702f`.
- 사용자 디자인 취향 (시안 4차에 걸쳐 정해짐): 읽기 쉬움 최우선, 로판풍 색, **장식 최소**, 사진 없음(성별 토글 때문에도), 이니셜 동그라미·말풍선·왼쪽 세로 막대·"자리에 없음" 줄 싫어함,
  접기 버튼 없음, 5인/단일 모드 구분 없음(있는 인물만). 테두리 장식만 로판풍. 이미지 테두리는 크기 변화 문제로 안 씀.

## 6. 남은 일

사용자가 채우기로 한 것 (README '채워 넣을 자리'와 같음): 영어 첫 메시지 본문, ♂ 프로필 5개 + 다프네야 ♂/♀, ♀ 프로필 실제 내용,
오리지널 카르엔야 상세·간략(리스트) 버전, NPC 목록 여자 키(지금은 남자 키 그대로, 다프네야만 168 cm),
`빙의상태 카르엔야 설정`의 남자 버전, `운명의 개입` 내용, `에셋출력식`, 다프네야 비밀 배치, 디스크립션 고치기, 궁정지도(?).

사용자가 바꾸면 따라 고쳐야 할 연결: 프로필을 채울 때 감싸는 조건은 그대로 둔다. 인물을 추가하면 토글 글(`kc_g_`/`kc_p_`) + NPC 목록 + ♂/♀ 항목을 같이 만든다.

## 7. 실제 RisuAI에서 아직 확인 안 된 것

소스 코드를 읽고 흉내 내서 확인했지만 실물로는 안 봤다. 사용자가 문제를 말하면 여기부터 의심한다.

- 토글 메뉴 모양 (divider·caption·group), 안 고른 칸이 빈칸으로 보이는지.
- 퍼메 버튼을 누르면 화면이 바로 바뀌는지 (v3에서 같은 구조로 작동했다고 들음).
- Google Fonts `@import`가 RisuAI에서 받아지는지. 안 되면 기본 serif/sans-serif로 보일 뿐 깨지진 않음.
- 실제 채팅 테마 안에서 상태창 카드 모양 (prose 스타일 덮어쓰기는 `!important`로 막아 둠).
- `Status 리퀘제거`의 `chat_index` 동작 (사용자 원래 정규식에서 물려받은 부분).

## 8. RisuAI 함정 (이번 작업에서 확인한 것)

- 설정 안 된 채팅 변수·토글은 빈 문자열이 아니라 `"null"`. 채팅 변수는 캐릭터 기본 변수(defaultVariables)로 대체된다. 토글은 UI만 쓸 수 있다 (버튼·CBS·Lua로 못 바꿈).
- `#if`는 deprecated → `#when`. `#when` 연산자는 오른쪽부터 스택으로 계산돼서 `A::tisnot::1::and::B::tisnot::2` 같은 연결은 틀린다.
  중첩하거나 `{{any::{{equal::…}}::…}}` 함수로 미리 만든다. 부정은 앞에 `not::X` (`X::not` 아님). 여러 줄 블록의 `{{:else}}`는 단독 줄에, 한 줄 블록은 같은 줄 안에서 가능.
  `#when`은 가장자리 빈 줄만 지운다 (`#if`는 각 줄 앞 공백까지 지웠음). 거짓 블록 안 CBS도 일단 계산된다.
- `{{// 주석}}`은 이 버전 소스에서 지워지는지 확실하지 않아 쓰지 않았다.
- 채팅·배경 HTML의 `class`는 전부 `x-risu-` 접두사가 붙고, `<style>` 선택자도 `.chattext .x-risu-…`로 바뀐다 → CSS는 평범하게 `.ks{}`로 쓰면 맞물린다.
  전역 `* { font-family: var(--risu-font-family) }`가 있어서 자식 글꼴은 `inherit !important`로 막았다. CSS 파서는 `@adobe/css-tools` 4.4.4 (따옴표 안 `;` 괜찮음).
- 정규식은 JS 엔진 (가변 길이 lookbehind 됨, 기본 플래그 g). OUT이 `>`로 끝나면 줄바꿈이 하나 붙는다. 마크다운이 HTML 블록을 빈 줄에서 끊으므로 HTML 출력에 빈 줄을 만들지 않는다.
- Lua (wasmoon 5.4): `getFullChat`은 1부터, 첫 메시지(greeting)는 채팅 배열에 없음. `editDisplay`의 `meta.index`는 0부터, greeting은 -1.
  토글은 `getGlobalVar(id, "toggle_kc_language")`, `cbs()`로 `{{user}}` 등 치환. `listenEdit`는 low level access 없이 된다.
- charx = zip(card.json, module.risum, assets/, x_meta/). 가져올 때 module의 lorebook/regex/trigger가 card.json보다 우선 → 로어북은 양쪽을 같이 고친다.

## 9. 작업 방법과 도구 (`kiryen/tools/`)

준비 (세션이 바뀌면 다시):

```
cd kiryen/tools
curl -sSLo rpack_map.bin https://raw.githubusercontent.com/kwaroran/RisuAI/main/src/ts/rpack/rpack_map.bin
pip install lupa playwright          # Chromium은 /opt/pw-browsers/chromium 에 이미 있음 (playwright install 금지)
npm install @adobe/css-tools@4.4.4 postcss-selector-parser@7.1.1   # 렌더할 때만
# 렌더용 글꼴 → ../design/fonts/ (GowunBatang-Regular.ttf, GowunBatang-Bold.ttf, NotoSansKR.ttf)
#   https://raw.githubusercontent.com/google/fonts/main/ofl/gowunbatang/GowunBatang-Regular.ttf (Bold도 같은 폴더)
#   https://raw.githubusercontent.com/google/fonts/main/ofl/notosanskr/NotoSansKR%5Bwght%5D.ttf → NotoSansKR.ttf 로 저장
```

| 도구 | 쓰는 법 |
|---|---|
| `charx_io.py` | `unpack 카드.charx 덤프.json` / `pack 원본.charx 덤프.json 새.charx`. 파이썬에서 `load()`/`save()` |
| `test_lua.py` | `python3 -I test_lua.py 카드.charx` — 트리거 Lua를 가짜 RisuAI API로 29가지 확인 (상태창 HTML, 언어, 막힘 연쇄, World State 문구) |
| `verify_card.py` | 토글 조합 580가지로 첫 메시지·퍼메 패널·로어북 CBS 결과 확인 + 옛 변수(`cv_`, `getvar::lang` 등) 잔재, 토글 이름, 버튼 함수, card/module 로어북 일치 검사 |
| `cbs_mini.py` | 위 검사에 쓰는 CBS 계산기 (RisuAI `parser.svelte.ts` 규칙을 옮긴 것: #when 연산자, :else, getvar/getglobalvar/any/equal…) |
| `render_status.py` | `python3 -I render_status.py 카드.charx 출력폴더` — 카드의 Lua로 상태창 HTML을 만들고 RisuAI와 같은 CSS 변환을 거쳐 PC 680px / 모바일 375px PNG |
| `risu_css.cjs` | RisuAI의 `decodeStyleRule` 그대로 (x-risu- 접두사, `.chattext` 범위) |
| `build_v4_from_v3.py` | 기록용. v3 → v4 변환을 한 스크립트 (어떤 문자열을 어떻게 바꿨는지 보려면) |

RisuAI 소스가 필요하면 `git clone --depth 1 --filter=blob:none https://github.com/kwaroran/RisuAI.git` (파서 `src/ts/parser/parser.svelte.ts`, Lua API `src/ts/process/scriptings.ts`, 정규식 `src/ts/process/scripts.ts`, 토글 `src/ts/util.ts`의 `parseToggleSyntax`).

작업 순서 (지금까지 해 온 방식): 사용자 카드 받기 → `unpack` → 파이썬으로 고치기(문자열 치환은 정확히 한 번 맞는지 assert) → `pack` →
`test_lua.py`, `verify_card.py`(새 조건을 추가하면 검사도 추가), 상태창을 건드렸으면 `render_status.py`로 그림 확인 →
카드와 관련 md·README 갱신 → 지정 브랜치에 커밋·푸시 → 파일을 사용자에게 보내고 쉬운 한국어로 "바뀐 것 / 확인할 것 / 채울 것" 정리.
사용자가 카드에서 직접 고친 뒤 보낸 파일이 있으면 반드시 그걸 기준으로 하고, 이전 버전과 달라진 부분을 먼저 확인한다.
